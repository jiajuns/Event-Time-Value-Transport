# ETSF 阶段 1 · 过夜执行文档

**给 agent 的一句话目标**：在 RoboTwin 四本体数据上实现事件时间共享后继头，冻结迁移到目标本体，产出三项核心测量。不设复杂验证门，跑完即可。

---

## 0. 先读：今天的数据改变了什么

阶段 0 与速度门跑完后，有三处发现直接改变了本阶段的设计。**请务必理解这三条，它们决定了下面每一步为什么这么做。**

### 0.1 速度门的"弱效应"结论是选择效应

速度门要求"四本体同任务同 seed 全部成功"才计入配对样本，因此自动排除了 `adjust_bottle` 与 `handover_block`。但恰恰是这两个任务上：

```
任务                    aloha   ARX-X5   piper   ur5-wsg
adjust_bottle            9/10     7/10    0/10      0/10
handover_block           9/10     8/10    2/10      0/10
lift_pot                 7/10     5/10    2/10      4/10
move_can_pot            10/10     7/10    9/10      9/10
```

**两个任务上有本体是 0/10。** 这是 `ρ_b` 从 0.9 到 0.0 的跨度——远大于 `κ` 从 1.0 到 1.66 的跨度。

门只测了时间尺度轴，而且是在可行性最均匀的子集上测的。**真实的跨本体差异主要在可行性，不在速度。**

### 0.2 因此：`ρ_b` 是主线，`λ_b` 是副线

原提案把两者当作并列参数。数据说不是。本阶段的主要测量围绕 `ρ_b` 展开，`λ_b` 作为次要机制与对照。

### 0.3 但 `κ` 的稳定性本身是一个好结果

同一本体对在四个不同任务上的 `κ`：

```
aloha/piper:  1.50, 1.38, 1.44, 1.43   ← 极稳定
aloha/ur5:    1.74, 1.40, 1.63, 1.62
piper/ARX-X5: 1.03, 1.03, 1.02, 1.02   ← 几乎为 1
```

`κ` 几乎与任务无关，说明 **`λ_b` 应当建模为全局标量而非状态相关的 `λ_b(z)`**。原提案消融 B 组第 4 项已被这份数据回答，不必再做。

### 0.4 送上门的解离设计

`piper` 与 `ARX-X5` 速度几乎相同（`κ=1.02`，93.75% 的样本 ≤1.1），但可行性差异巨大（`handover_block` 8/10 vs 2/10，`adjust_bottle` 7/10 vs 0/10）。

这给出一组天然的机制解离：

| 迁移对 | κ | ρ 差异 | 分离出的机制 |
|---|---|---|---|
| ARX-X5 → piper | ≈1.02 | 大 | **纯 `ρ_b`** |
| aloha → ARX-X5 | 1.44 | 小 | **纯 `λ_b`** |
| aloha → ur5-wsg | 1.66 | 大 | 两者叠加 |

**这比单一迁移实验强得多**：如果 ETSF 的收益在第一行来自 `ρ_b`、在第二行来自 `λ_b`、在第三行两者叠加，机制就被直接证实了。反之如果三行收益相同，说明分解没有捕捉到真实机制。

| # | 产出 | 判断什么 |

## 2. 阶段 A · 数据

### 2.1 优先下载，不要优先生成

[已验证] RoboTwin 2.0 为每个「任务 × 本体」对提供 100 条干净轨迹与 400 条域随机化轨迹。**先尝试直接下载**，只对缺失的部分做生成。生成成本约 20–60 秒/episode，全量生成会吃掉整夜。

先查 RoboTwin 官方下载脚本与 HuggingFace 上的分本体数据；`StarVLA/RoboTwin-Clean` 是已知的 LeRobot 格式镜像，但**是否覆盖全部四个本体需要确认**。若只覆盖 aloha，则其余本体需生成。

### 2.2 任务优先级（时间不够时按此顺序砍）

```
1. adjust_bottle          ← ρ 跨度 9/10，M2 的核心
2. handover_block         ← ρ 跨度 9/10，M2 的核心
3. move_can_pot           ← ρ 均匀、κ 可测，λ 机制的干净样本
4. place_container_plate
5. beat_block_hammer
6. lift_pot
```

**前三个必须有。** 后三个是加分项。

### 2.3 本体与数据量

```
源本体：aloha-agilex, ARX-X5        每任务 50 条成功轨迹
目标本体：piper, ur5-wsg            每任务 20 条 rollout
```

**目标本体的 rollout 不要过滤成功。** `ρ_b` 就是从失败率估出来的——在 `adjust_bottle` 上 piper 全部失败，这些失败轨迹是最有信息量的数据，丢掉就没法估 `ρ`。

记录每条轨迹的：图像帧、物体位姿序列、成功标志、总步数。

### 2.4 唯一的检查点

如果前三个任务在四个本体上都拿不到数据，停下报告。其他情况一律继续，用手上有的数据跑完全流程。

## 3. 阶段 B · 事件字母表（本阶段的核心新实现）

### 3.1 设计原则

事件必须**只引用物体状态，绝不引用机器人变量**。这是整个方法成立的前提，也是唯一不可妥协的地方。

不要为每个任务手写谓词——那会吃掉整夜且不可推广。用一套**通用的物体运动学谓词**，从记录的物体位姿序列自动导出：

```
e_0  起始
e_1  物体开始运动     首次 |v_object| > τ_v
e_2  物体离开支撑面   物体 z > z_init + δ_z
e_3  物体接近目标     到目标区域距离 < τ_d
e_4  物体静止于目标   在目标区域内且 |v_object| < τ_v 持续 k 帧
e_K  任务成功         仿真器的成功标志
```

阈值用**每个任务上跨全部本体的合并数据**标定一次（例如取物体速度分布的分位数），**不要按本体分别标定**——那会把本体差异偷偷编进事件定义里，破坏整个实验。

### 3.2 M1：立刻验证核心假设

事件抽完之后，**第一件事是检查事件序列是否跨本体一致**：

- 每个「任务 × 本体」的事件序列众数是什么
- 同一任务下不同本体的事件序列是否相同
- 各本体在每个事件转移上的到达率（这直接就是 `ρ_b` 的经验估计）
- 各本体的事件间隔步数分布（这直接就是 `λ_b` 的原料）

**把这个结果单独存一张表。** 如果事件序列跨本体不一致，说明要么阈值标定有问题，要么本体确实改变了事件偏序（提案 §3.6 预言的失效模式）——两种情况都必须在早上被看到，不能埋在训练日志里。

### 3.3 记录事件间隔

对每条轨迹记录 `D_j`（第 j 段事件间隔的控制步数）。后面 `λ_b = E[γ^D]` 直接从这里算，不需要训练。

## 5. 阶段 D · 模型训练

三个模型，**共享同一批数据、同一冻结骨干、同等容量的头**。这是可比性的前提。

### 5.1 ETSF 共享后继头

```
Ψ^evt_T(z, λ) : 折扣条件化的事件时间后继占用
输出维度 = |事件字母表| = 6
```

**在事件边界之间做 TD**，不是控制步之间：

```
y_j = φ^evt_j + λ · (1 - done_j) · sg[ Ψ̄(z_{j+1}, λ) ]
L   = E_{λ~p(λ)} [ Huber( Ψ(z_j, λ), y_j ) ]
```

`z_{j+1}` 取下一次事件转移发生时的任务状态。`λ` 训练时从 `{0.5, 0.7, 0.9, 0.95, 0.99}` 采样并作为条件输入。

**只在源本体（aloha, ARX-X5）上训练。** 目标本体的数据在这一步完全不参与。

### 5.2 控制时间基线（主对照）

RECAP 式剩余步数回归，**同样只在源本体上训**，同样的骨干和容量。这是阶段 0 里失真最大的那个模型（相对失真 1.72），也是你论文的主基线。

### 5.3 归一化进度对照

保留阶段 0 的归一化进度模型作为下界参照。

## 6. 阶段 E · 三项测量

### 6.1 估计本体参数（不训练，纯统计）

对每个目标本体，从其 rollout 直接算：

```
λ_b = mean_j( γ^{D_j} )            γ 取 0.99
ρ_b[j] = P(到达事件 j | 已到达事件 j-1)    用 Beta(1,1) 先验平滑
```

**同时报告估计精度随 rollout 数的收敛曲线**（N = 5, 10, 15, 20）。这是"不需要信用分配"这个主张的直接证据——如果 N=10 就稳定，统计阶段的成本可以忽略。

### 6.2 M2 · 零样本可行性预测

用冻结的 `Ψ^evt_T` 加上从 N 条 rollout 估出的 `ρ_b`，预测每个「任务 × 目标本体」的成功率，与真实成功率对比。

**关键案例**：piper 在 `adjust_bottle` 上真实成功率为 0。预测出来了吗？用了几条 rollout？

报告：预测成功率 vs 真实成功率的散点图 + 相关系数，以及 0/10 那几格的单独结果。

### 6.3 M3 · 残差有效维度

```
R(s) = Ψ^ctrl_target(s) − ρ_b ⊙ Ψ^evt_T(z, λ_b)
```

`Ψ^ctrl_target` 用目标本体 rollout 的蒙特卡洛估计。对 `R` 做 PCA，报告前 k 个主方向的解释方差与参与比。

**必须同时跑三个对照**，否则这个数字没有意义：

| 对照 | 做法 |
|---|---|
| 控制时间基线的残差维度 | 证明降维来自坐标而非拟合 |
| **错配本体** | 用本体 b' 的 `(λ,ρ)` 去解释本体 b |
| **随机 λ** | 随机取 λ 值 |

### 6.4 M4 · 目标域 Bellman 残差

ETSF（冻结 + 估计参数）vs 控制时间基线（冻结）vs 从零训练，在目标本体上比较 Bellman 残差与价值排序 AUC。

### 6.5 M5 · 机制解离

对三对迁移分别跑 6.2–6.4：

```
ARX-X5 → piper      预期：ρ_b 贡献大，λ_b 贡献 ≈ 0
aloha  → ARX-X5     预期：λ_b 贡献可见，ρ_b 贡献小
aloha  → ur5-wsg    预期：两者叠加
```

**同时跑消融**：只用 `λ_b`、只用 `ρ_b`、两者都用。九个组合（3 迁移对 × 3 消融）的结果做成一张表。

如果三行收益相同、消融无差异，说明分解没有捕捉到真实机制——**如实报告，这是重要的负结果**。

## 9. 不要做的事

- ❌ 不要在事件定义里引用任何机器人变量（关节角、末端位姿、夹爪状态）
- ❌ 不要按本体分别标定事件阈值
- ❌ 不要过滤掉目标本体的失败轨迹——`ρ_b` 就在那里面
- ❌ 不要用目标本体数据训练共享头
- ❌ 不要为了让 M3 好看而调整 `λ` 或丢弃对照
- ❌ 不要跑完整 VLA 或 RL——本阶段全部在冻结特征上完成
